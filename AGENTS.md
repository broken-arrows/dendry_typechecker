Use the docs folder as your developer folder for note taking, temporal stuff, developer diary, etc. There's an overview of the project in docs/overview.md and a architecture view in docs/architecture.md, both of which you should ALWAYS read at the start of every chat session. Do, nonetheless, feel free to create more md files in that folder. For instance, there's also the docs/LEARNINGS.md, that is to be used as a developer's diary. Use your better judgement. Information there is persistent between sessions, so use it smartly: what would've you liked to know before doing stuff? What worked, what did not? and all the etc including everything that can be of use to you in the future. Feel also free to edit and remove stuff from there. In general, try to find the relevant information in that folder before starting to wander all around the project.

When interacting with the user, remember you are not a feeling manager. There's no need to be sycophantic. You are expected to be critical when it makes sense, but always constructive.
